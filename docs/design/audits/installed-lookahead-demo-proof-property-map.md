# Installed-lookahead proof-to-property map

Status: in progress for the admitted Regex demo slice. This map distinguishes a compiled theorem, an executable generated property, an example-based regression, and an assumption still requiring runtime refinement. None is substituted for another.

The principal source model is [InstalledLookaheadEveryTrace.v](../../../formal/rocq/runtime_grammar/theories/InstalledLookaheadEveryTrace.v); [LookaheadTraceDelivery.v](../../../formal/rocq/rho_bridge/theories/LookaheadTraceDelivery.v) and [LookaheadUnsignedBound.v](../../../formal/rocq/rho_bridge/theories/LookaheadUnsignedBound.v) state the adjacent public-wire obligations. The admitted runtime domain is one closed installed root or one exact top-level reflected expression beside ordinary Rholang processes. Nested or transported guests, multiple active guest slots, and provider-aware installed-guest resumption are refused. The broader model's multi-slot statements therefore do not establish that those shapes work in Rust. The [integration contract](../plans/installed-gslt-lookahead-integration.md) describes the public boundary and its diagram.

## Reading the evidence

An executable property below means a generated test that calls production code, not a second implementation of the matcher. An example is useful regression evidence but does not exhaust an input family. A Rocq theorem is conditional on its stated hypotheses: in particular, `CompleteRoster` asserts that enumeration is complete, and the abstract `HostChecker` is not a proof of RSpace matching. The formal files end each theorem in `Qed` and print assumptions for their exported results; compilation and its assumptions output must still be checked in the campaign's serialized Rocq gate. The one-step semantic validator checks witness shape and bounds; concrete receipt production and host charge correspondence require separate implementation evidence.

## Declaration inventory and runtime correspondence

Production seam: [lookahead request encoding](../../../rholang-runtime/src/lookahead.rs) and [request parsing/admission](../../../rholang-runtime/src/speculation/server.rs). `generated_request_channels_keep_legacy_host_and_installed_authority_disjoint` exercises 128 generated host-expression bags and guest placements. It checks ordinary host preservation on the legacy and v2 channels, refusal of an installed guest without an owner claim, and disjoint v2/v3 decoding in both directions. `request_operands_are_read_or_refused`, `versioned_request_enforces_exact_ordered_binding_paths`, and the public Regex application test remain complementary examples. This property establishes channel separation for the admitted one-top-level-guest domain, not arbitrary multi-slot envelopes.

### Complete roster, receipts, and work

Model declarations: `fired_roster_retains_exact_occurrences`, `fired_roster_receipts_and_work_are_exact`, `fired_roster_has_no_guest_committable_effects`, and `guest_occurrence_has_positive_logical_work`.

Production seam: [installed provider](../../../rholang-runtime/src/speculation/installed_provider.rs) `complete_roster`, the existing one-step kernel's `ProvenSteps`, and [Explorer](../../../rholang-runtime/src/speculation/search.rs). `generated_one_slot_roster_matches_the_shared_kernel_occurrence_for_occurrence` checks 128 generated Regex patterns over plus, optional, and star shapes. For each pattern it calls the established kernel and provider independently, compares roster cardinality, every ordinal, owner/image commitment, exact target key, and encoded proof receipt, and checks the kernel's aggregate-work report. It also checks that one additional primitive-work diagnostic receipt covers the aggregate. In cost-accounted Rholang, primitive work is diagnostic while COMMs consume source-token units; a flat `RuntimeBudget::remaining()` delta would be the wrong assertion. `checked_equal_target_proofs_survive_existing_bfs_as_distinct_paths` remains an example of BFS retention. Full Rust-to-Rocq grade, effects, and component-work refinement is not established by this model and belongs to the broader correspondence.

The generated `generated_mixed_trace_preserves_every_edge_and_terminal_state` and `generated_host_only_trace_preserves_legacy_public_path` properties cover exact trace extension and legacy public-path identity. `generated_installed_guest_and_host_comm_keep_both_bfs_interleavings` additionally runs 128 installed Regex/host-COMM combinations through the production search, requiring both edge orders, identical host and guest edge identities across orders, and the same terminal configuration. `generated_host_roster_refines_every_trace_first_level_on_finite_stores` compares production host enumeration with one-step EveryTrace expansion on 64 generated finite stores with independent and competing COMMs. Each source and search run uses the same explicit random seed; the property requires one leaf per enabled rendezvous, no merge or pruning, and exactly one matching first-step identity and successor-store fingerprint for every enumerated occurrence. `trace_last_edge_extend`, `map_trace_last_edge_extend`, and `last_snoc` are proof-local steps discharged by the generated extension property. `host_only_roster_orders` and `increasing_seq` are proof-local order lemmas. The abstract `HostChecker` does not discharge the concrete correspondence by itself; the generated production comparison provides evidence for this admitted finite-store domain, not a proof for every possible host store.

Production seam: `ReductionTrace::extend_guest` and [PathMap delivery](../../../rholang-runtime/src/speculation/delivery.rs). ### Full unsigned lookahead bound

Related model: [LookaheadUnsignedBound.v](../../../formal/rocq/rho_bridge/theories/LookaheadUnsignedBound.v). `admitted_bound_round_trips`, `admitted_source_bound_round_trips`, `decoded_bound_is_unsigned`, `old_wire_is_preserved`, and `upper_unsigned_half_uses_big_integer` correspond to `generated_unsigned_lookahead_bounds_round_trip_through_the_request_wire`: 256 generated `u64` values pass through the production encoder and request decoder with the exact value, subject, reply channel, and small-integer/big-integer carrier preserved. `signed_max_below_unsigned_max` is proof-local arithmetic. `negative_source_bound_is_refused`, `overflowing_source_bound_is_refused`, `first_big_integer_bound_round_trips`, and `maximum_unsigned_bound_round_trips` have boundary examples in `lookahead_bound_admits_exact_unsigned_range_without_narrowing`, `full_unsigned_lookahead_bounds_use_existing_source_parser_and_exact_wire`, and `request_bound_accepts_full_u64_and_rejects_noncanonical_wide_values`. Generated invalid-source and malformed-big-integer families remain open. The model reasons about decoded integer values; canonical signed-byte encoding is a separate Rust codec obligation.

## Verification boundary

The property names above are runnable tests, not declarations of campaign completion. The newly added wire properties need the serialized Rust gate before they count as passing evidence. The remaining generated properties include exhaustion/cancellation and public-publication boundaries for the admitted slice; the actual-owner resume example is not a generated revocation family. The general multi-slot abstraction map, concrete enumeration completeness beyond tested finite stores, host-store transport, full receipt/work refinement, and cross-language authority policy require the separate broader proof and implementation. No parser, matcher, automaton, or rewrite relation is re-derived to close a test gap.
