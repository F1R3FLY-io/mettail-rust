Optimal channel naming, by example

An interactive tutorial for Optimal Channel Naming for Compositional Rewrite Translations via Set Automaton Partial Evaluation.

The paper compiles a rewrite system into a rho-calculus process. The hard part is the contextual rules — rules of the form L → R ⇒ K(L) → K'(R), where firing the outer rewrite requires the inner rule to fire first inside some context K. The compiled outer rule listens for the inner match on a channel tc(K), and the trick is choosing that channel so that (a) every function symbol of K is inspected at most once, and (b) firing inner rewrites doesn't invalidate the outer for-receive's listening state.

The construction: build a Bouwman–Erkens set automaton from the left-hand-side patterns of the rule set, then define tc(K) = ⌜δ*(s₀, surface(K))⌝ — the canonical reflection of the automaton state that the surface of K walks the automaton to. Below we work through every piece of this construction for the lambda calculus, then watch it find redexes in a nontrivial term.

1. The lambda calculus as a rewrite system

We want full β-reduction: a redex anywhere inside the term should be firable. As a term-rewriting presentation that is one principal rule plus three contextual rules — one for each position a hole can sit in relative to a lambda-calculus constructor.

  • β app(lam(x, M), N) ⇝ M[N/x]
  • CtxF M ⇝ M′  ⇒  app(M, N) ⇝ app(M′, N)
  • CtxA M ⇝ M′  ⇒  app(N, M) ⇝ app(N, M′)
  • CtxB M ⇝ M′  ⇒  lam(x, M) ⇝ lam(x, M′)

Each contextual rule has an outer context that pinpoints where the hole sits: K_F = app(□, N) for CtxF, K_A = app(N, □) for CtxA, K_B = lam(x, □) for CtxB. N is a schema variable — a stand-in for any subterm the rule does not inspect.

There is only one LHS pattern in the rule set: app(lam(x, M), N), the β-LHS. The contextual rules don't introduce new patterns — they only say that the same β-pattern, when it matches deeper inside, can fire and the surrounding shape gets rebuilt.

A note on variables. The two function symbols of the signature are app (arity 2) and lam (arity 1, body-binding). There is no separate var constructor: in a GSLT the closedness of the host category gives an internal hom P ⇒ P, so lam : (P ⇒ P) → P is the ordinary HOAS reading and object-level variables are just free names of the host calculus. The tree leaves you see below — x, y, v, etc. — are exactly those free names, not var(x) cells. The matcher only ever dispatches on app and lam head symbols; reaching a leaf means there is no function-symbol head to dispatch on, so the walk just terminates there.

2. The rho-calculus translation of a rewrite rule

A single rewrite rule L ⇝ R compiles to a process listening on a channel for the LHS pattern, and sending the RHS on the same channel when the match arrives. Reading ⟦t⟧ as the rho encoding of t:

⟦L ⇝ R⟧(tℓ)  =  for (⟦L⟧ ⇐ tℓ) { tℓ ! ⟦R⟧ }

A contextual rewrite is trickier. The outer for-receive must wait for the inner match to land, then emit the rebuilt outer term. The polymorphic step is choosing the channel tc the for-receive listens on:

⟦L₁ ⇝ R₁, ..., Lₙ ⇝ Rₙ  ⇒  K(L₁,...,Lₙ) ⇝ K′(R₁,...,Rₙ)⟧
  =  let tc = ⟦K⟧ in
       for ((⟦L₁⟧, ..., ⟦Lₙ⟧) ⇐ tc) {
         tc ! ⟦K′(R₁,...,Rₙ)⟧
       }

The whole question of optimality reduces to one question: what is ⟦K⟧? The paper's answer is the set automaton.

3. The set automaton for the β-pattern

A set automaton for a pattern set L is a deterministic tree-walking automaton that recognises every occurrence of every pattern in L, visiting each function symbol of the input at most once. We build it once, offline, from the β-LHS. The construction (which the paper inlines from Bouwman–Erkens 2022) yields exactly two reachable states; before we can write down its transition table, we need a word on positions and configurations.

Positions, configurations, and what (s, q) means

A position is a path from the root of a term, written as a dot-separated sequence of 1-indexed child indices (with ε for the root). For app(f, a), position 1 is f and position 2 is a; for lam(x, body), position 1 is body; 1.2 means "child 2 of child 1 of the root", and so on. Position concatenation is just path concatenation: p · q appends q after p.

A configuration is a pair (s, p) where s is an automaton state and p is an absolute position — the configuration's base in the term being walked. The actual symbol the automaton inspects from configuration (s, p) is the one at p · L(s): the base position composed with the state's inspection offset L(s).

The same (s, q) notation gets used in two slightly different ways, which is the most common stumbling block when reading the paper:

  • In the δ table below the q is a position offset, relative to whatever the current configuration's base is. The entry δ(s₀, app) = {(s_app, ε), (s₀, 2)} reads: "if a configuration with base p in state s₀ reads app, spawn two new configurations — (s_app, p · ε) = (s_app, p) and (s₀, p · 2)." The 2 here means "go to the argument child."
  • In the Pending list of the live matcher (§6), the q is an absolute position — the cumulative path from the root after all the concatenations.

Same syntax, two reference frames. In both cases the digit 2 always means "argument child of an app"; what changes is whether it's measured from the configuration's base or from the root.

stateL(s)reads appreads lamη(s, ·)
s₀ ε {(s_app, ε), (s₀, 2)} {(s₀, 1)} ∅
s_app 1 {(s_app, ε), (s₀, 2)} ★ {(s₀, 1)} η(s_app, lam) = { β-LHS @ ε }

The table covers both head symbols of the signature. When the inspection position p · L(s) sits on a leaf (a free name) instead of a function symbol, there is nothing for δ to dispatch on, so the configuration simply terminates with no spawns and no announcement — that is the third case, and the only thing the matcher does at leaves.

Reading the table:

  • State s₀ means "I'm searching for a β-redex at the current base position." Its label L(s₀) = ε says to inspect the symbol at the base position.
  • State s_app means "I've already seen an app at the base position and I'm checking whether the function child (offset 1) is a lam to complete the match." Hence L(s_app) = 1.
  • The δ entry {(s_app, ε), (s₀, 2)} means: when state s₀ sees app at the inspection position, spawn configuration (s_app, base) — same base, will inspect the function child — and configuration (s₀, base·2) — start a fresh redex search in the argument.
  • η records match announcements. The only nonempty entry is η(s_app, lam) = {β-LHS @ ε} — when s_app actually sees a lam at offset 1, it announces a β-redex at offset ε (i.e., at the base position, which is the position of the app).

The automaton's job is to compute tc(K) for the contextual rules — its states s reflect to channel names ⌜s⌝ that appear as components of tc(K) in the next section. The principal β-rule itself is compiled by the plain template of §2 against its own dedicated channel tβ:

for (⟦app(lam(x, M), N)⟧ ⇐ tβ) { tβ ! ⟦M[N/x]⟧ }

(tβ is just a fresh channel name; nothing automaton-derived about it. The automaton-derived channels are tc(K) for each contextual rule, below.)

4. Channel naming: from context to channel

For each contextual rule, the channel tc(K) is computed by walking the automaton against surface(K) — the partial term that is K, with every hole and schema variable treated as an opaque "I don't know what's there yet" symbol the automaton can't inspect. The walk produces a tree of configurations with some of them suspended at the holes; reflecting that tree of suspended configurations gives the channel name.

Here are the three contextual contexts of §1, with the automaton trace that tc reflects:

The orange dashed boxes are holes / schema variables — positions the automaton suspends at. The suspended configurations on those boxes together are the channel: any two contexts whose surface walks suspend at the same configurations get the same tc. This is why the channel-quotient is the coarsest equivalence sound for matching (Theorem 5.3 of the paper).

5. The compiled lambda calculus

Plugging the four rewrite rules into the templates of §2, with channels named by the automaton states of §4:

// principal β-rule — listens on its own dedicated channel tβ
for (⟦app(lam(x, M), N)⟧ ⇐ tβ) { tβ ! ⟦M[N/x]⟧ }

// CtxF: reduce in the function position of an app
let tc_F = ⌜trace(K_F)⌝ in
  for (⟦β-LHS⟧ ⇐ tc_F) { tc_F ! ⟦app(β-RHS, N)⟧ }

// CtxA: reduce in the argument position of an app
let tc_A = ⌜trace(K_A)⌝ in
  for (⟦β-LHS⟧ ⇐ tc_A) { tc_A ! ⟦app(N, β-RHS)⟧ }

// CtxB: reduce in the body of a lam
let tc_B = ⌜trace(K_B)⌝ in
  for (⟦β-LHS⟧ ⇐ tc_B) { tc_B ! ⟦lam(x, β-RHS)⟧ }

The principal β-rule has a fixed listening channel tβ; the contextual rules' channels are automaton-derived. The matcher's job is to walk a term once and route each announcement of a β-match to tβ so the principal rule fires, with the β-RHS then arriving on the appropriate tc(K) of whichever contextual rule wraps the redex position. Different positions in the term that reach the same automaton state share a tc, so their contextual rules' for-receives share their matching work — that's the entire trick.

6. Reducing a term: the matcher in action

Pick a term and step the matcher. It runs the same automaton you saw in §3, configuration by configuration. Every position gets exactly one configuration; the for-receive on each (reflected) state is the listener that would fire if the corresponding rule's LHS arrives. When you click fire on an announced redex, the demo:

  1. Substitutes the β-reduct in place (this is the contents of the send that the compiled β-rule would emit).
  2. Discards configurations strictly inside the fired subtree (the symbols they inspected don't exist anymore).
  3. Restarts the matcher with one initial configuration at the fired position — the for-receive on the appropriate outer-context channel will now match this position's new shape.

The configurations outside the fired subtree are preserved: those for-receives stay live on their channels across the firing. This is the rho-calculus realisation of the prune-preserves-work theorem.

7. Why this is optimal

The paper transports three optimality theorems from Bouwman–Erkens into this rho-calculus setting:

Symbol-once (Theorem 5.1). Every function symbol of K is consumed by exactly one for-receive. In the demo: #nodes inspected equals the number of function symbols in the term, no matter how many redexes are firing.

Prune-preserves-work (Theorem 5.2). Firing a redex at position p does not invalidate any for-receive whose channel reflects an automaton state reached at a position outside p's subtree. The demo logs this on every fire: how many configs got pruned, how many were preserved.

Coarsest-sound (Theorem 5.3). Two contexts share tc(K) = tc(K′) exactly when no choice of hole-filler can distinguish them from the rule set's standpoint. This is the strongest possible sharing — any coarser equivalence on contexts would let some hole-filler fire a rule in one and not in the other.

How the matcher implements the rho semantics

The simulator queues configurations and steps them one at a time (BFS over the configuration tree). One configuration step corresponds to one for-receive consuming a send in the rho semantics: the configuration's state determines which channel the send/receive pair uses, and the spawned configurations correspond to the body of the for-receive (which is itself a parallel composition of further for-receives waiting on successor-state channels).

A redex announcement corresponds to the matcher routing a send to the principal β-rule's channel tβ. When you click fire, the demo carries out that send-receive communication: the principal β-rule's for-receive on tβ reads the matched β-LHS, runs its body (the substitution), and emits the result on the surrounding contextual rule's channel tc(K) — which is the channel reflected from the automaton trace of whatever context K wraps the redex position.

Connection to the paper's lambda example (§5.1)

The paper works out the head-reduction case in detail — only context K_F = app(□, N). The construction here is the obvious generalisation: build the same set automaton from the same β-pattern, then add a contextual rule (and a corresponding channel) for each of the three structural positions a hole can sit in. The automaton states and labels (s₀, s_app, L(s_app) = 1) are unchanged.
