## §2 The prefix-trie mechanism (construction + per-divergence emission + identical-emission proof)

The transform lives ENTIRELY in `binder.rs`, in two phases mirroring the two existing emission functions: (A) `emit_binder_prefix_arms` (the group's prefix arm) and (B) `emit_binder_rule_body` (the per-position chains). Today these are independent; the trie unifies a group's rules into a SHARED skeleton, then emits the prefix arm + the body arms FROM the trie.

### §2.0 Position equality — the structural key (no literals, no category ids)

The trie's edge labels are `BinderPosition`s compared by a STRUCTURAL equality `pos_key(p) -> PosKey` that captures shape, not identity-of-a-known-token:

```
enum PosKey {
    Lit(String),            // Literal(text)        — keyed by the text VALUE (whatever it is)
    Param(String),          // ParamParse{cat,None} — keyed by cat NAME (whatever it is)
    ParamColl(CollKey),     // ParamParse{Some(info)} — keyed by (elem_cat, separator, close, coll_kind)
    Binders(BinderLoopKey), // BinderListLoop        — keyed by (separator, close, allow_empty, allow_multi, inner shape)
    Guard,                  // GuardSlot
    OptGroup(u8),           // OptionalGroup         — keyed by group_idx (+ recursively by inner shape)
}
```

`pos_key` reads `Literal`'s text as an opaque `String` and `ParamParse`'s `cat` as an opaque `String` — it NEVER tests `text == "(" / "," / ")"` or `cat == "Int"`. Two positions share a trie edge iff `pos_key(a) == pos_key(b)`. This is the ONLY place structure is inspected, and it is purely value-equality over the lowered fields. **This satisfies the mandate: any literal, any category, any arity, any rule-count flows through identically.**

### §2.1 The trie data structure + construction algorithm (over `Vec<BinderPosition>`, any length)

For a group `entries: Vec<RuleEntry>` (each carrying `shape.positions` + `rule_idx` + `body_src_idx`), build a **prefix trie**:

```
struct TrieNode {
    // children keyed by the structural PosKey of the edge taken to reach them
    edges: BTreeMap<PosKey, (BinderPosition, TrieNode)>,   // BinderPosition kept verbatim for emission
    // rules whose position-sequence ENDS exactly at this node (arity-terminal here)
    terminal_rules: Vec<RuleRef>,                          // RuleRef = (rule_idx, body_src_idx, action_args)
}

fn build_trie(entries) -> TrieNode:
    root = TrieNode::empty()
    for e in entries (in source/rule_idx order — determinism):
        node = &mut root
        for p in e.shape.positions:
            k = pos_key(p)
            node = &mut node.edges.entry(k).or_insert((p.clone(), TrieNode::empty())).1
        node.terminal_rules.push(RuleRef::from(e))
    root
```

`BTreeMap<PosKey,_>` gives deterministic edge order (so emission is reproducible). Each node's outgoing structure is one of:
- **0 edges, ≥1 terminal_rule** — a leaf (rule(s) end here).
- **1 edge, 0 terminal_rules** — a non-branching prefix link → emit the edge action and descend (this is the "emit the shared prefix ONCE" case).
- **≥2 edges, and/or ≥1 terminal_rule alongside ≥1 edge** — a DIVERGENCE node → emit an evidence dispatch (§2.3).

**Trie classification of the calculator groups (computed, for the M0 dump):**
- `("float", Float)`: root —`Lit("(")`→ N1 (1 edge, the shared open). N1 —`Param("Int")`→leaf(11), —`Param("Bool")`→leaf(12), —`Param("Str")`→leaf(13), —`Param("Float")`→leaf(14), —`Param("Proc")`→N2. N2 —`Lit(",")`→…→leaf(15). So N1 is a 5-edge divergence on the **ParamParse category** (Int/Bool/Str/Float/Proc); the Proc edge continues to N2 which is itself a divergence (`)` would close — but no unary took the Proc edge — vs `,` continues). The fold is the lone Proc-continuation; the four unaries are the four typed leaves after their own `)`.
- `("int", Int)`: structurally identical (FloatToInt/BoolToInt/StrToInt/IntId + IntBin).
- `("str", Str)` and `("bool", Bool)`: root —`Lit("(")`→ N1, N1 has 5 (resp. 5) edges `Param("Bool"|"Int"|"Float"|"Str"|"Proc")` each →leaf — a PURE category-divergence, NO fold, NO arity split. The trie handles these uniformly (§2.4) — and this is where the design SUBSUMES the narrow one, which ignored `str`/`bool` entirely.
- Every single-rule group → root —…→ a single chain of 1-edge links to one leaf → byte-identical to today's `ConsumeAndPush` (§2.5).

### §2.2 Threading `body_src_idx` / `outer_bp` / weights through the shared chain

A shared-prefix edge must be emitted with state that is correct for ALL rules sharing it. The fields:
- **`outer_bp`** — bound at the prefix arm from `_outer_bp` (the caller's BP); identical for all rules in a group (it is the dispatch-site BP, not rule-specific). Threaded verbatim.
- **`result_src_idx`** — the group key; identical for all rules. Verbatim.
- **`body_src_idx`** — `match shape.body_cat { Some(name) => lookup_src_idx(name), None => result_src_idx }` (`:1100-1103`). For a SHARED prefix edge, `body_src_idx` may differ per rule ONLY if `body_cat` differs. For all cast groups every rule has `body_cat: None` ⇒ `body_src_idx == result_src_idx` for all (confirmed generated `wpda.rs`: float rules 11-15 all `body_src_idx:5`). **General rule:** a shared-prefix edge is emitted with a single `body_src_idx` ONLY when all rules sharing it agree; if they disagree, that edge is NOT shared (the trie splits earlier — see §2.8 invariant). Since `body_src_idx` is a function of the prefix-determined `body_cat`, rules that share a position-prefix that includes the body-defining position necessarily agree; rules that diverge before it carry their own `body_src_idx` on their own (post-divergence) sub-chain. **No new `body_src_idx` value is ever synthesized** (R5 of the narrow plan, generalized).
- **`rule_idx` in the marker symbol** — the shared-prefix chain must carry SOME rule_idx in its `rule_at(result, rule_idx, pos, ...)` symbol and `BinderRule{rule_idx}` state, because the body-arm match key is `(result, rule_idx, pos)`. The trie assigns each shared-prefix edge a **canonical rule_idx** = the minimum rule_idx among rules passing through that edge (deterministic). Crucially, this is the SAME mechanism as the FLIP: the FLIP collapses the float prefix to `ConsumeAndPush→BinderRule{rule_idx:15}` (or the canonical fold idx) and the shared body arms run under that one idx until divergence; at a divergence the cursor transitions to the DIVERGED rule's own `rule_idx`. **The weight on a shared-prefix edge is `lex_one()`** (the existing per-position weight — see `Literal` arm `:1238`), NOT a `lex_w(0.0, result, rule_idx)` that would re-introduce a rule_idx tiebreak. The only `lex_w(0.0,result,rule_idx)` is on the prefix ENTRY arm and on genuinely-Forked divergence alternates (where the guard, not the weight, decides — §2.3), so the rule_idx component is inert to the choice (it only well-forms the surviving cursor's downstream packing, as today).

This threading is exactly what `emit_binder_rule_body` already does for a single rule's chain; the trie's contribution is to emit the SHARED chain once under the canonical idx and to re-key the post-divergence sub-chains under each diverged rule's own idx.

### §2.3 Per-divergence-kind emission (the heart — all by EVIDENCE)

At a trie node with multiple outgoing edges and/or a terminal-rule-alongside-edges, emit ONE dispatch arm at the chain's current position. The dispatch kind is determined by the `PosKey`s of the outgoing edges (purely structural):

**(D1) Divergence on `Lit` edges + possibly a terminal-here.** All outgoing edges are `PosKey::Lit(text_i)` (the texts differ), and/or the node has terminal_rules (a rule ends here while others continue). Emit a single `Fork` whose branches are:
- one `GuardedConsumeAndReplace{expected_text: text_i}` branch per `Lit` edge (transition to that edge's sub-chain, re-keyed to the edge's canonical rule_idx);
- if there are terminal_rules here AND at least one continuing edge, the "rule ends here" outcome is the arity-end (D3) handled by the NEXT token being the parent's close/separator — but at a pure-`Lit`-divergence node the terminal case is itself just "the rule had no further positions," which is the `final_pos → Pop` arm already emitted for that rule (no extra branch needed; the cursor that took no edge simply isn't created — see D3).

By R0.6, `GuardedConsumeAndReplace` allocates a child ONLY if `peek_text == text_i`. Since the `text_i` are distinct, **at most one branch survives** — pure token evidence, never rule_idx. *The float position-3 `,`-vs-`)` decision is exactly D1* (two `Lit` edges `,` and `)`; whichever token is present picks fold-continue vs unary-close). **No hardcoded `,`/`)`** — the branch texts are whatever `text_i` the lowering produced.

**(D2) Divergence on `Param` (category) edges.** Outgoing edges are `PosKey::Param(cat_i)` (categories differ) — e.g. float N1's Int/Bool/Str/Float/Proc. Here the divergence is on the OPERAND'S category, which is NOT yet known at the dispatch point (the operand hasn't been parsed). Two sub-cases by whether the categories are FIRST-token-distinguishable:

  - **(D2a) Distinguishable by FIRST-set** (the categories have disjoint FIRST-token sets, computable at codegen via `first_set_of_category` — the same routine `prefix.rs:1000` uses): emit a `Fork` whose branches are guarded by the operand's FIRST token (peek_kind / peek_text), each pushing `category_entry(cat_i)` for the matching edge. At most one survives by token evidence. This is the operand analogue of `prefix.rs`'s FIRST-set cross-cat-LHS dispatch — reuse that exact pattern.

  - **(D2b) NOT distinguishable at the dispatch point** (categories share FIRST tokens — e.g. Int/Bool/Str/Float/Proc literals or a nested cast keyword that could project to several): **keep ALL viable category-alternates alive as a Fork**, each pushing its own `category_entry(cat_i)` and descending into its own sub-chain, until LATER evidence (the realized operand's category at the closing token + `min_terminal_span` at realize) prunes. This is the genuinely-ambiguous case: the choice CANNOT be made by rule_idx (invariant), so it stays Forked. **This is exactly today's behavior** for the float unaries (they already Fork and parse the operand in 5 categories), with ONE difference: the shared `(` prefix is consumed ONCE before the Fork, and the Fork now also carries the fold's Proc edge as a co-equal alternate decided downstream by D1 at position 3 — which is the FLIP. The genuinely-indistinguishable category alternates survive to EOI and resolve via the EXISTING multi-root `Ambiguous` arm (`:4376`) + `min_terminal_span` filter — first-class, capped, unchanged.

  **The unified D2 emission (recommended, fully general):** since D2a is a strictly-pruned special case of D2b (a FIRST-set guard that happens to leave one branch), emit D2 UNIFORMLY as a Fork over `category_entry(cat_i)` branches, optionally annotated with a FIRST-set `peek` guard when `first_set_of_category(cat_i)` is disjoint from the siblings (turning a `Push` branch into a guarded branch that self-prunes). When FIRST-sets overlap, branches are unguarded `Push` (co-equal, decided downstream). **No category NAME is ever matched** — the branches are generated by iterating the node's edges; the guard (when present) is computed from the category's FIRST-set, not from `cat == "Int"`.

  *Critical refinement for the fold's Proc edge (the FLIP):* the fold's `Param("Proc")` edge and the four unaries' typed edges are siblings at N1. Proc's FIRST-set is the UNION of all operand FIRST-sets (Proc is the join — `ProcInt`/`ProcFloat`/… projections), so D2a never fires to exclude the unaries; D2b keeps them co-equal. The decisive evidence is at position 3 (D1: `,` vs `)`), reached AFTER the operand parse. This is precisely why the FLIP works: the operand is parsed once (widest = Proc covers all), and the `,`/`)` token — not rule_idx — selects fold-continue vs unary-close. See §2.6 for how the typed-unary leaves are reconciled with the single Proc operand parse.

**(D3) Arity divergence (one rule ENDS where another continues).** A node has `terminal_rules` (rule R ends here) AND ≥1 outgoing edge (rule R' continues with position `p`). The "R ends" outcome is realized by R's `final_pos → Pop→InfixLoop` arm (already emitted, `:1210`); the "R' continues" outcome is the edge's action. These are mutually exclusive by the NEXT token: R ends ⇒ the parent frame's next expected token (a closer/separator at the enclosing level) follows; R' continues ⇒ `p`'s first token follows. **The decision is made by whichever arm's guard matches the peeked token** — i.e. D3 is emitted as D1/D2 over {R's implicit "no more positions" (which surfaces as the parent's close consuming the control) } ∪ {R''s continuing edge}. In the cast grammar D3 manifests AS D1 (the float fold's `Param("Proc")` edge leads to N2 where `Lit(",")` continues vs the unary leaves whose `)` already closed) — so D3 reduces to D1+D2 at the shared trie and needs no separate primitive. For a HYPOTHETICAL group where rule R = `kw ( a )` and R' = `kw ( a , b )` share `[Lit("("), Param(a)]` and diverge at "R has `Lit(")")` next vs R' has `Lit(",")` next," that node has TWO `Lit` edges (`)` and `,`) → pure D1. **Arity-end is always decided by the realized next token, never rule_idx.** (No fixed arity assumed: a 3-arg fold `kw(a,b,c)` is just a longer chain `Lit("(") Param Lit(",") Param Lit(",") Param Lit(")")`; it shares the `[Lit("("), Param, Lit(",")]` prefix with a 2-arg fold and diverges at the 2nd `Lit` node = D1 over `,` vs `)`.)

**(D4) Mixed-`PosKey` divergence (defensive, general).** If a node's outgoing edges have DIFFERENT `PosKey` variants (e.g. one `Lit`, one `Param`, one `Binders`) — possible for an arbitrary DSL group — emit a Fork that DISPATCHES by the variant-appropriate guard per branch: `Lit` branches use `GuardedConsumeAndReplace` (token-peek); `Param`/`ParamColl` branches use a FIRST-set `peek` guard (or co-equal Push if indistinguishable); `Binders` branches use `peek_kind == Ident`/close-peek (the existing BinderListLoop bootstrap guard, `:1462`); `Guard` branches enter `ParsePredicate`; `OptGroup` branches use the group's `first_token_set` (already computed, `:210`). Each branch self-prunes on its own evidence; indistinguishable branches stay co-equal. **This is the fully-general catch-all** — it composes the per-`BinderPosition` emission rules (R0.3) under one Fork, guarded by each position kind's natural FIRST evidence. For the shipped grammars D4 never fires (cast nodes are homogeneous: all-`Lit` (D1) or all-`Param` (D2)), so it is inert today, but it guarantees the trie is TOTAL over the position alphabet (no DSL group can produce a divergence the trie cannot emit).

### §2.4 Pure-unary category groups (`str`, `bool`) — subsumed, not special-cased

`str`/`bool` are `root —Lit("(")→ N1` with N1 a pure D2 category-divergence (5 typed edges, no fold, no arity split). The trie emits: consume `(` once (shared, canonical idx), then a D2 Fork over the 5 `category_entry` branches. This is BEHAVIORALLY equivalent to today's 5-way flat Fork (each unary parses its operand in its own category, decided by realize), BUT the `(` is consumed once and the rule_idx pre-commit at the prefix is gone (replaced by the category Fork at N1 where the operand evidence — not rule_idx — decides, with indistinguishable alternates co-equal to EOI). The narrow design left these as flat Forks (untouched); this design folds them through the SAME trie, which is strictly more uniform and removes their latent rule_idx pre-commit. **Gate consequence:** `str`/`bool` standalone + nested casts must stay green (they do today; §6 re-asserts) — this is a behavioral-equivalence obligation, validated at M0 (emission diff) + M5 (green).

### §2.5 No-shared-prefix → BYTE-IDENTICAL emission (the #1 no-regression PROOF)

**Claim:** for any group where the trie root has no shared multi-rule structure, the emitted `WpdaStepAction`s are byte-identical to today.

**Proof.**
1. **Single-rule group** (`entries.len()==1`): `build_trie` produces a spine of 1-edge links (root→…→one leaf), with NO node having ≥2 edges and NO node having terminal-alongside-edge (the single rule occupies the whole spine, terminal only at the final leaf). The trie emission rule for a 1-edge/0-terminal node is "emit the edge's action and descend" = exactly the per-position arm `emit_binder_rule_body` emits today; the prefix-arm emission for a single-leaf trie is the existing `ConsumeAndPush` (`:1095-1135`) under that rule's idx. Since there is exactly one rule, the canonical idx == the rule's idx, weights/body_src_idx/outer_bp/trigger_mode are computed by the SAME expressions. ⇒ **byte-identical.** (Covers ALL of rholang's casts, all binders, all collections, all single folds — the bulk of every language.)
2. **Multi-rule group where rules share NO position-0 edge** (`pos_key(r.positions[0])` all distinct, e.g. a hypothetical group of rules with different first literals — though in practice same-trigger rules share the trigger, which is already stripped): the trie root has N edges, 0 shared links. The root divergence is emitted by D1/D2/D4 — BUT when no two rules share even position 0, each branch is the rule's FULL chain entered by its own first-position guard. The flat-Fork today enters each rule via `Push` at the prefix arm then runs its full body chain. The trie's root-divergence Fork enters each rule via its first-position guard then runs the SAME body chain. **These differ** (guard vs unguarded Push at entry) ONLY if the rules' first positions are distinguishable; if they are NOT distinguishable they stay co-equal Push = identical to today. **To guarantee byte-identity for the genuinely-no-shared-prefix case, the trie emission SHORT-CIRCUITS:** if `build_trie(entries).edges.len() == entries.len()` AND every edge leads directly to a leaf-spine with no inter-rule sharing (i.e. the trie is just N independent spines under the root with no shared prefix), emit the EXISTING flat Fork verbatim (`:1138-1177`) — the trie added nothing, so emit nothing new. **This is the explicit no-regression guarantee:** the trie's output is the flat Fork UNLESS ≥2 rules share a non-empty position prefix (a shared root edge with >1 rule beneath it). Only calculator's `float`/`int`/`str`/`bool` satisfy "≥2 rules share the `Lit("(")` edge."
3. **Therefore** every group in every language EXCEPT calculator's 4 emits byte-identically (single-rule → existing `ConsumeAndPush`; multi-rule-no-sharing → existing flat Fork). Calculator's 4 emit the trie (shared `(` + evidence dispatch). ∎

The M0 gate makes this PROVABLE per-build: dump the trie classification + the emitted `WpdaStepAction` token stream for every group of every language and assert it is `Plain`/flat-Fork (hence byte-identical to a `B6`-disabled build's generated `wpda.rs`) for all but the 4 calculator groups. STOP if any other group's emission changes.

### §2.6 Generic unary-close derivation (NEVER hand-referencing `calc_try_*` or `{Int,Bool,Str,Float}`)

The hard sub-problem (flagged by the mandate): at float N1, the fold's `Param("Proc")` edge parses the operand as Proc; on the `)`-close evidence (D1 at the fold's would-be position vs the typed-unary leaves), WHICH typed unary action (`IntToFloat`/`BoolToFloat`/…) fires? The narrow plan's "U-PROC" hardcoded a Proc-unary collapse. The GENERAL derivation:

**The unary-close action set is DERIVED from the group's OWN declared rules, per-source.** At a D2 category-divergence node, each typed edge `Param(cat_i)` carries a terminal rule R_i whose action is R_i's OWN declared semantic action (`IntToFloat`'s `![CanonicalFloat64::from(a as f64)]`, etc. — already lowered into the per-rule action entry). The trie does NOT consolidate or rewrite these actions. Instead:

- **The operand is parsed in its OWN typed category on each typed edge** (exactly as today — `category_entry(Int)` for the IntToFloat edge, `category_entry(Bool)` for BoolToFloat, …). Each typed edge is a distinct Fork branch (D2). They are co-equal (D2b) because their FIRST-sets overlap (a bare integer literal could be Int, or could be the Proc operand of the fold). Each typed branch then closes with its OWN `)` (D1) and fires its OWN declared action. **This is byte-identical to today's per-rule body chains** — the trie did not touch the typed unaries' bodies; it only factored the shared `(` and added the fold's Proc edge as a co-equal sibling.
- **The fold's Proc edge** parses the operand as Proc, then at position 3 the `,` evidence (D1) selects fold-continuation; the `)` evidence would (on the Proc edge) select… nothing — the fold has no `)`-at-position-3 leaf. So on `)`, the Proc-edge cursor finds no matching D1 branch and DIES (empty-children). The typed-unary cursors (which parsed the operand in Int/Bool/Str/Float and are at their OWN `)`) survive on `)`. On `,`, the typed-unary cursors find no `,`-branch (their position 3 is `Lit(")")`) and DIE; the fold's Proc cursor survives. **The `,`/`)` token prunes exactly one side — pure evidence.**

So the GENERIC unary-close is: **each declared unary fires its OWN declared action via its OWN typed operand parse and its OWN `)`-close arm — emitted exactly as `emit_binder_rule_body` does today.** The trie adds nothing to the unary bodies; it only (a) factors the shared `(` so it's consumed once, and (b) makes the fold's first-operand parse a co-equal sibling rather than a rule_idx-dominated loser. **No source category is enumerated in codegen; no `calc_try_*` is referenced; each rule's action is its own.** The "single Proc parse serves all" framing of the narrow plan is NOT needed and NOT used — the typed parses remain typed, co-equal, evidence-pruned. (The `BigintCast`/`ProcToBool` Proc-operand unaries — R0.8 — remain as they are: single-rule groups, `Plain`, untouched. They are not part of any mixed trie because `bigint`/`bigrat` are distinct single-rule triggers.)

**Why this is the FLIP, exactly.** The FLIP (`FLIP_NOUNARY=1`) dropped the 4 unary branches so the inner `float(` collapsed to the fold. This design does NOT drop the unaries; it makes them co-equal-with-the-fold under a shared `(`, so the inner `float(10,64)` — which has a `,` — prunes the four unary readings (their position 3 is `)`, no `,` arm) and keeps ONLY the fold (FloatBin), which then parses, projects to Proc, and fills the outer slot. The OUTCOME is identical to the FLIP (inner reads as FloatBin) but the MECHANISM is evidence (the inner `,`), not branch-deletion — so standalone `float(10.5)` (no inner `,`) still prunes the FOLD and keeps the unary, parsing correctly. **The FLIP proved the structural collapse works; the trie achieves it by evidence rather than by deletion, recovering the standalone-unary case for free.** This is the precise generalization.

### §2.7 Operator/prefix dispatch (`prefix.rs`) — uniform argument, why no change is needed

By R0.7, every `prefix.rs` arm is FIRST-token-keyed via the Rust match guard. Two arms with different first tokens are mutually exclusive by Rust dispatch (the analogue of D1 at the LANGUAGE level — the "trie" is the match statement itself, branching on `TokenKind`). The only intra-arm Fork (`emit_atomic_arm_fork`, same `(pat,guard)`) is over 0-position atomic rules that share no multi-position prefix — there is no prefix to factor, and the choice is among co-equal atomic captures decided by lex-min/realize (genuinely ambiguous, first-class). **The prefix-sharing premature-disambiguation root is structurally absent from `prefix.rs`** because operator rules don't emit N branches that each run a multi-position body chain through `emit_binder_rule_body` — they `ConsumeAndPush→Unwinding` (atomic) or `→CrossCatDelegate` (cross-cat) or `→BinderRule` for a SINGLE rule (unary-prefix). The trie is therefore applied ONLY in `binder.rs` (the unique N-branch-multi-position site). `prefix.rs` is emitted byte-identically (no code change); §6 cross-cat + op-suite gates + the gauntlet are the tripwires confirming neutrality. *(If a FUTURE DSL introduced ≥2 multi-position operator rules sharing a token prefix in the same category, the SAME trie could be lifted into `prefix.rs`'s `UnifiedBucket` emission — the design generalizes there unchanged — but no shipped grammar needs it, so it is out of scope and not built; documented as a clean extension point.)*

### §2.8 Trie well-formedness invariants (enforced at construction, asserted at M1)

- **I1 — shared edge ⇒ agreeing fixed state.** A shared-prefix edge (a node link traversed by >1 rule) is emitted with a single `(result_src_idx, body_src_idx, outer_bp)`; construction ASSERTS all rules through the edge agree on `body_src_idx` (they do, since `body_cat` is prefix-determined — §2.2). If a (hypothetical) group violated this, the trie MUST split that edge per-rule (don't share) → falls back toward the flat Fork for that subtree. Asserted, not silently mis-shared.
- **I2 — divergence ⇒ evidence or co-equal.** Every node with ≥2 outgoing edges emits D1/D2/D4 (guarded or co-equal), NEVER a rule_idx-ranked pick. Asserted: no emitted Fork at a divergence relies on lex-min `rule_idx` to choose among same-`(primary,lex_alt,src)` branches that are NOT mutually-exclusive-by-guard — except the genuinely-indistinguishable D2b/D4 co-equal case, which is INTENDED (stays alive to EOI → Ambiguous).
- **I3 — totality.** `pos_key` + the D1/D2/D3/D4 dispatch cover ALL `BinderPosition` variants (R0.1). A node whose edges include a variant with no emission rule is impossible (D4 is the catch-all). Asserted by an exhaustive `match` on `BinderPosition` in `pos_key` + the divergence emitter (Rust exhaustiveness check at compile time).
- **I4 — emission determinism.** `BTreeMap<PosKey,_>` edge order + source-order `terminal_rules` ⇒ identical token stream across builds. Asserted by the M0 emission-diff being stable.

## §3 Termination / boundedness (RIGOROUS; cursor-count bound proven)

- **B1 — peak cursor count at the prefix STRICTLY DECREASES or holds.** Today a multi-rule group fans out N cursors at the prefix arm (float: 5). The trie emits a single `ConsumeAndPush` for the shared `(` (zero fan-out) IF there is a shared root edge; the first Fork is at N1 (the first divergence). At N1, the D2 category Fork has at most N branches (= today's N), of which the FIRST-set-distinguishable ones (D2a) self-prune to ≤ the indistinguishable count, and the indistinguishable ones (D2b) are exactly the alternates today already keeps alive. **Net: peak `branch_cursors` at every step ≤ today's** (one step LATER, because `(` is consumed before the fan-out instead of at it). For pure-`Lit` divergence (D1), at most ONE branch survives (distinct guards, R0.6) — a strict DECREASE from N to 1. ⇒ The trie never increases peak cursor count; it strictly decreases it at every `Lit`-divergence (the arity/comma points) and holds it at category-divergences. Formally: `peak_trie(step) ≤ peak_flat(step)` for all steps, with strict `<` at any step containing a D1 node.
- **B2 — evidence prune is O(1) tokens.** Each D1/D2a guard is a single `peek_text`/`peek_kind`/FIRST-set check at the current position (R0.6); the losing branches allocate no child within the SAME `step_fanout` (`:8936`, empty-children). No paren-balanced scan, no lookahead loop, no re-parse. The D2b co-equal alternates are pruned by the SAME realize-time `min_terminal_span` + accepting-set logic that prunes them today (no new pruning mechanism, no new cost).
- **B3 — GLL/recovery bounds unchanged.** The new arms reuse `ConsumeAndPush`/`Fork`/`GuardedConsumeAndReplace`/`ReplaceAndPush`/`category_entry`/`Pop` — the EXACT actions already governed by GLL descriptor-uniqueness (`wpda_walker.rs:6644`), the bounded-recovery cycle defense (`:6599`), and the CrossCatDelegate cycle guard (`:5859`). No new action kind, no new state variant, no new recursion. The walker is UNCHANGED, so all its termination proofs hold verbatim.
- **B4 — genuine ambiguity terminates at the cap.** D2b/D4 indistinguishable alternates that survive to EOI hit the `accepting_indices.len() >= 2` arm (`:4376`) → multi-root `Ambiguous`, realized under the existing realize cap. This is the SAME path the float unaries take today; the trie adds the fold as one more co-equal alternate, which the `,`/`)` evidence almost always prunes before EOI (so in practice ambiguity is REDUCED, not increased). Bounded by construction.
- **B5 — no unbounded fan-out introduced.** The trie REDUCES branching (factors shared prefixes) and PRESERVES the alternate set (no alternate dropped, none added beyond the co-equal fold that was already a rule). It cannot introduce a non-terminating cycle the flat Fork didn't already have, since it emits a SUBSET-or-equal of the flat Fork's cursor population at every step (B1). ∎
