### 1.1 The LIVE implicit-coercion synthesis — WHERE + HOW (code-confirmed)

The grammar's implicit cross-category coercion is synthesized at **prefix-dispatch time** during a forward sub-parse, by TWO codegen passes in `macros/src/gen/runtime/wpda_codegen/prefix.rs` (both fold into the SAME `unified_buckets` → `emit_unified_arm`):

- **Pass 2a — `UnifiedDescriptor::CrossCatProjection`** (`prefix.rs:~1086`): for TRANSPARENT cast rules `ProcFloat . f:Float |- f : Proc` (sp.len()==1, no trigger). Emits, for each `ft ∈ FIRST(source)`, a `Push { symbol: StackSymbolV2::rule_at(target_cat, rule_idx, slot=0, Some(_outer_bp)).with_kind_return(), new_state: CrossCatDelegate{ source_src_idx, inner_cur_bp:0 } }`. Weight `BP_TIER_CROSSCAT_PROJECTION` (0.025).
- **Pass 2c — `UnifiedDescriptor::ImplicitCast`** (`prefix.rs:1041–1194`, emission arm `prefix.rs:~1481` singleton / `~1601` multi): for TRIGGER-BEARING syntactic casts `<Y>To<X> . a:Y |- "trig" "(" a ")" : X` (`IntToBool`, `BoolToInt`, `StrToInt`, …; sp.len()≥3, `tc=[Simple{Base(Y)}]`, `Y≠X`). Same emission shape — `Push { rule_at(target_cat, rule_idx, 0, _outer_bp).with_kind_return(), CrossCatDelegate{source} }` — at `BP_TIER_PASS2C_SYNTHESIZED` (0.15, `lex_weight.rs:283`).

The MECHANISM (both passes): when the target category's prefix dispatch sees a `FIRST(source)` token, it pushes a `with_kind_return` `RuleAt(target, cast_rule, …)` and delegates to `source`-parsing via `CrossCatDelegate`. The source body parses normally; on the **`Return` pop**, `apply_pop_body_to_cursor` (`wpda_walker.rs:13593`, base) → `emit_fire_action` (`:11787`, base) fires the cast rule's action over the just-parsed source Symbol, producing a NEW target-category SPPF Symbol whose realized term is stored in `sppf_symbol_terms[wrap_symbol_id]` (`:12065`, base). The cast's `"trig"`/`"("`/`")"` literals are NOT matched (slot=0) — soundness is enforced separately by the realize-time `min_terminal_span` filter (§1.4).

**Why boollit-first PASSES at Blocker-2 but the var-first revival does NOT.** For `int(true != y > x < "qua")` (boollit-first), the body sub-parse encounters `true` (a Bool-unique FIRST token) and the LIVE forward dispatch synthesizes the coercions in-line as it parses — the implicit-cast Push happens DURING the live worker's forward walk, so the body resolves AS the correct category and the outer cast fires normally without any revival. For `int(y != true > x < "qua")` (var-first), the bare `y` is FIRST-ambiguous; the outer `int(` continuation is paused as a `pending_member` and only revived at the EOI fixpoint (§1.5 of the M5.1 doc) — by which point the body is a FINALIZED SPPF Symbol and the implicit-cast Push window has passed.

`[C6-1]` (live-synthesis site): a `SIGB_CROSSWRAP`/codegen-diag print confirms that for the boollit-first PASSING input `int(true != y > x < "qua")`, the body's resolution involves a Pass-2c `ImplicitCast` (or Pass-2a `CrossCatProjection`) Return-pop fire that produces the target-category Symbol — i.e. the LIVE path synthesizes the coercion at dispatch, NOT at revival. ## 2. Mechanism — coercion-aware splice at the revival site, REUSING the live `<Y>To<X>`/`ProcX` action fire (ONLY if M6.0 confirms a category-correct body exists)

> **Gating precondition.** This entire section is contingent on `[C6-3]`/`[C6-4]`/`[C6-5]` PASSING. If M6.0 falsifies them, STOP+report per §7 R1 — the residual is then a (B)-class outer-frame-from-SPPF problem, out of scope for a splice-shape, and the cast family closes via a different (future) plan. The plan below is the design IF the confirm holds (i.e. a category-correct full-span body, or a one-hop-coercion-reachable body, IS in the cohort cache once the over-fire is constrained — see §2.1).

### 2.0 Why a NEW coercion is NOT invented — reuse the live primitive

The synthesis primitive already exists and is exercised on every passing cross-cat parse: fire the grammar's `<Y>To<X>` (Pass-2c) or `ProcX` (Pass-2a) action over a source Symbol to produce a target Symbol whose term is stored in `sppf_symbol_terms`. The coercion-aware splice REUSES this exact fire — it does NOT add a new coercion, weight, or heuristic. The coercion chosen is the grammar's specified one (the `<Y>To<X>` cast rule / the transparent projection), selected by matching `(body_category → target_category)` against the grammar's cast-rule table. If MULTIPLE coercions bridge `(body_cat → target_cat)`, ALL are emitted as distinct spliced cursors (Ambiguous stays first-class — §4); none is picked by weight/threshold.

### 2.1 Constrain the over-fire FIRST (prerequisite to a correct splice)

The 16251-cursor blowup (§1.3) is itself a defect: the `equiv()`-blind pairing splices every member with every wrong-category body. Before/with the coercion shaping, `take_outer_cast_revival` MUST be tightened so a member is paired with `R` ONLY when `R`'s realized body category is COMPATIBLE with the member's cast (either `== target_arg_cat`, or one grammar-coercion-hop away). Concretely, ADD a clause to the Pass-2 eligibility scan (`dispatch_cohort.rs:~1755`, the `for (k_sib, entry)` loop):

- **Clause 5 (NEW — category compatibility):** read `body_cat = sppf.node(R.symbol_id)→Symbol.category_src_idx`. Determine the member's cast target-arg category `tgt_cat` from `(K_sib.wrap_cat, K_sib.wrap_rule)` (the member's own cast rule — its `source` operand category is the grammar-declared `a:Y` of that rule). Accept the pair iff `body_cat == tgt_cat` OR `∃` a grammar cast/projection rule `coerce: body_cat → tgt_cat`. Reject otherwise (do NOT materialize → cuts the 16251 to the handful of genuinely-coercible pairs). This requires the cache/job to carry `(wrap_cat, wrap_rule)` for `K_sib` (already present — `DispatchKey.wrap_cat/wrap_rule`, patch `dispatch_cohort.rs:74`) and a read-only grammar coercion-table query on the engine (§2.3).

This is NOT a heuristic prune by weight — it is the EVIDENCE constraint that a cast's arg must be type-reachable. It strictly REDUCES non-evidence drops (it stops materializing cursors that provably cannot fire), preserving the WPDA invariant.

### 2.2 The coercion-aware splice — interpose the `<Y>To<X>`/`ProcX` Symbol between body and cast

Modify the revival so that, when `body_cat != tgt_cat` but a single grammar coercion `coerce: body_cat → tgt_cat` exists, the body Symbol is WRAPPED before the outer cast fires. Two cooperating changes:

**2.2a — `CrossWrapSpliceJob` carries the coercion (`dispatch_cohort.rs`, struct at patch `:1271`).** Add `coercion: Option<CoercionStep>` where `CoercionStep { rule_global_idx: u32, target_cat: u16 }` names the grammar `<Y>To<X>`/`ProcX` rule to interpose (None when `body_cat == tgt_cat`, the byte-identical M5.1 path). `take_outer_cast_revival` fills it from the §2.1 clause-5 match. If multiple coercions bridge, emit one job per coercion (Ambiguous).

**2.2b — `revive_cohort_member_with_snapshot` (or a thin wrapper) interposes the coercion Symbol (`wpda_walker.rs:13480`, base).** Currently (`:13517`) it does `cursor.sppf_stack_id = intern_push(cursor.sppf_stack_id, symbol_id)` — pushing the RAW body Symbol. Change: when `job.coercion = Some(cs)`, FIRST synthesize the wrap Symbol from the body Symbol using the SAME intern+fire shape as `emit_fire_action`'s success arm (`:12045–12065`, base):
1. `packing_id = sppf.intern_packing(cs.rule_global_idx, &[body_symbol_id], W::one())`.
2. `wrap_symbol_id = sppf.intern_symbol(cs.target_cat, lo, hi)`; `link_packing_to_symbol`. (`lo`/`hi` = the body Symbol's span — identical, since a transparent/zero-token coercion adds no extent; this keeps `slack ≥ min_terminal_span` for transparent projections.)
3. Fire the coercion rule's action over the body Symbol via the existing `fire_action_via_transient` (`:11660`, base) to obtain the target-category result Arc; store it `sppf_symbol_terms.insert(wrap_symbol_id, result_arc)` (`:12065`). This is the IDENTICAL store the live Return-pop fire does — so the subsequent `reconstruct_action_arg` (`:11572`, base) reads `ActionArg::Term{ value: Arc<target>, … }` and the outer cast's `into_term::<tgt>()` SUCCEEDS.
4. `intern_push(cursor.sppf_stack_id, wrap_symbol_id)` (the WRAP, not the raw body).

When `job.coercion = None`, the path is byte-identical to M5.1 (push the body directly). The genuine outer cast then fires on the next step exactly as today, but over a category-correct (possibly wrapped) child → reaches `is_accepting_config` → consumes `)` → parks accepting.

**2.2c — chained coercions (≤1 hop only).** Per the SyntheticInjGuard depth-1 precedent (`auto_inject.rs:274–362`, which bounds the runtime NormCast cascade at depth 1) and the Pass-2c "OVERLY BROAD / transitive chaining" hazard (`prefix.rs:1130`, the `bool(0)→FloatToBool(IntToFloat(0))` bug), the splice interposes AT MOST ONE coercion. If `body_cat → tgt_cat` needs ≥2 hops, the pair is REJECTED in §2.1 clause 5 (no single-hop coercion) — never chained at the splice. This matches the live path (the live Pass-2c emits depth-1 implicit casts; transitive chains are the known-unsound case the `min_terminal_span` filter rejects).

### 2.3 The grammar coercion-table query (read-only engine method)

§2.1/§2.2 need "does a single grammar coercion `from_cat → to_cat` exist, and what is its `(rule_global_idx, target_cat)`?". This is a STATIC, grammar-determined table. REUSE existing infrastructure rather than build new:
- The Pass-2a/2c emission already enumerates exactly these rules (`prefix.rs` `is_cross_cat_unary_cast` / `CrossCatProjection` classification; mirrored in `parse_alt_filter.rs:41` `is_cross_cat_unary_cast`). Add a codegen-emitted `WpdaEngine::single_hop_coercion(from_cat: u16, to_cat: u16) -> Option<(u16 /*rule_idx*/, u16 /*target_cat*/)>` (a `match (from, to)` table, sibling to `min_terminal_span`'s emission in `engine_impl.rs:1795`). It enumerates every `<Y>To<X>` (sp.len()≥3, Y≠X) AND every transparent projection `ProcX`/cross-cat `CrossCatProjection` (sp.len()==1), keyed `(source_cat → target_cat)`. This is the SAME rule set the live synthesis uses — guaranteeing the splice's coercion ≡ the live coercion (HARD CONSTRAINT: follows the grammar's specified coercion, not a heuristic).
- Ambiguity: if two rules share `(from, to)` (rare; e.g. an `XToY` cast plus a transparent `YProj` both bridging), `single_hop_coercion` returns ALL of them (a slice), and §2.2a emits one job each.

### 2.4 Reject (B) reconstruct-the-body-from-Pratt-SPPF (if `[C6-3]` fails)

This plan does NOT pursue (B) — it is a larger mechanism, out of scope. M6.0's `[C6-3]` is precisely the gate that decides splice-shape (in scope) vs. (B) (STOP).
