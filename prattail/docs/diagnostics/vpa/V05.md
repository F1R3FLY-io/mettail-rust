# V05: visible-alphabet-conflict

**Severity:** Warning
**Module:** M4 VPA
**Feature gate:** `vpa`

## What it detects

V05 reports that the grammar analysis cannot form a valid visibly pushdown
alphabet because at least one terminal has conflicting structural roles. A VPA
requires the call, return, and internal partitions to be pairwise disjoint.

The historical diagnostic name `weighted-vpa-non-determinizable` is retained
in the machine-readable lint catalog for compatibility. The diagnostic is not
a theorem that some valid VPA is intrinsically nondeterminizable: every
nondeterministic Boolean VPA has an equivalent deterministic VPA. It reports a
failed representation precondition.

## Example

```text
call symbols:     { "(", "|" }
return symbols:   { ")", "|" }
internal symbols: { "id" }
```

The token `|` occurs in both the call and return sets, so the classification
is not visible. The same input symbol would request both a push and a return.

```text
warning[V05]: VPA alphabet has 1 conflicting symbol classification
  = hint: assign each terminal exactly one call, return, or internal role
```

## Correction

Choose a single structural role for each token, or split a context-dependent
surface token into distinct lexical tokens before VPA analysis:

```text
call symbols:     { "(", "bar-open" }
return symbols:   { ")", "bar-close" }
internal symbols: { "id" }
```

Changing grammar rules merely to reduce nondeterministic branching is not
required for correctness. The exact determinizer handles nondeterminism with
summary states $`(S,R)`$ and retains call/stack/return correlation.

## Why this matters

Visibility is the decidability boundary. If one input symbol can be interpreted
as either push or return depending on a control-state choice, the model is no
longer a VPA. Exact complement, inclusion, and equivalence therefore validate
the partition and fail closed on overlaps.

V05 does not invoke weighted determinization and does not compare quantitative
semiring values. `weighted_run` remains available for structurally valid
`WeightedVpa<W>` values, while exact language decisions currently use
`BooleanWeight`.
